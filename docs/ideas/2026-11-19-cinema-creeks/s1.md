# Session 1: Fresh version on launch

## Done
- Found the cause: GitHub Pages sends every file with a 10-minute cache and the game's ~230 modules have no version in their URLs, so a launch (installed app or tab) could run an old copy, or old modules under a new page. No service worker involved.
- `tools/stamp-release.sh` (run by the Pages and itch deploys) now also writes `version.json` (`release` plus the list of game files) beside `index.html`; `version.json` ships in the website build (`tools/build-website.mjs`) and the itch archive.
- `js/fresh-version.js`: at launch `main.js` fetches `version.json` with `cache: 'no-store'`; if the release differs, it refetches every game file with `cache: 'reload'` (a plain reload only revalidates the page, not the modules) and reloads, once (a sessionStorage guard prevents loops). Offline or no `version.json`: just plays.
- Mid-game: every 10 minutes and whenever the tab comes back, it checks again; on a newer release it autosaves and shows a toast "A new version of Second Growth is ready. Your farm is saved." with a Reload button (saves, refreshes the cache, reloads). Never reloads by itself.
- Local copies (`RELEASE = 'dev'`) never update. `tools/fresh-version-check.mjs` (headless suite) covers launch bump, mid-game bump, loop guard, offline, dev.
