## Done

- **Trails still draw. The check's test scene had gone stale.** `animal-trails-browser-check` saw 0 pixels of trail in both Fast and High, on main's code as well as this branch's.
  - Found with `git bisect` (browser check at each step): it broke at 9add1d3, "Creeks bend in curves and shores follow smooth lines" (0054). That commit's shore pass reshapes the land on the PNW map, and the trail test's small elk herd stands on that land.

  - The check's limit is unchanged (over 100 pixels must change). It now sees about 1,300 pixels change in Fast and High. The old seed passed with 147, just over the limit.

  - Recorded in 0010's History.
- **Full browser suite run locally** (`check-release.mjs --browser`, 29 scripts): everything passed except `first-minutes-browser-check`, "after 20 s without a stroke, the drag hint shows".
  - It passes when run alone. The check backdated the last stroke and then waited a fixed 300 ms for the hint, which is set on the next game frame. With the machine busy, one software-drawn frame took longer than that.

## New ideas noticed

- Other test pages may replay hand-picked run seeds that break the same way when animals or maps change. A quick search for `wildRng.setState(` in `tools/*.html` would find them. Recommended: give each one the same pick-the-strongest-seed treatment the next time one breaks, not before.
- Other browser checks wait a fixed few hundred milliseconds for something that happens on the next frame (`setTimeout(r,300)` and similar). On CI's slower machines these can flake the same way. Recommended: a short sweep that turns them into "wait until it shows, up to N s" waits.
