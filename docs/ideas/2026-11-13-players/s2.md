# Session 2: game feedback and newsletter prompt

## Done
- `js/backend.js`: one constant `BACKEND_URL` (empty until the Worker is deployed), an anonymous player id (`sg-player`), and `postBackend`.
- Feedback (`js/analytics.js`, `openFeedback`): with the address set it posts to `/feedback` (source `game`, player id, game snapshot, version) and still sends the PostHog event when play data is allowed. With it empty it behaves as before. `sendFeedback` now returns `{ ok, error }`; `analytics-privacy-check` updated for that.
- "Open an issue on GitHub" replaced by "Prefer email? Write to info@secondgrowth.earth" (mailto). The note stays in the box when sending fails; a rate-limit gets its own message.
- Newsletter card (`js/ui/newsletter.js`): a dismissible card in the notification stack (not a modal) with an email field, posting to `/subscribe` with source `game`. Shown once ever, only on a device's first play (no `sg-visited` and no saved settings), after at least 20 minutes of active play (tab visible, clock running) and the first year over, whichever is later; never with a modal, photo, watch or moment open, or while a campaign chapter is active. Dismissed or subscribed is remembered in `sg-news`.
- "Get updates by email": a menu button and a link inside the feedback box, both hidden while the address is empty.
- Spanish strings for all of it in `js/lang/es.js`.
- Checked in a browser at 812x375 against a stub endpoint (card, bad email, subscribe, feedback success and failure; request bodies match the contract). Constant and CSP were reverted afterwards. `backend-check`, `species-name-count`, `analytics-privacy-check` pass.
